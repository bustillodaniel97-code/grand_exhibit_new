## Continuation update — visitor clumping fixed

The top-priority visitor pile-up was diagnosed and fixed after this handoff was
written. It was **not** caused by `REST_CHANCE`, seat dwell, physical collision,
or doorway serialisation. `_waiting_to_cross()` used one-sided y comparisons,
so any indoor north/south path near the zebra crossing's x coordinate could be
mistaken for a pedestrian stepping off a kerb. A car over the zebra therefore
froze whole groups inside Promotions around grid y 11.

The crossing predicate now requires the visitor to be within 0.14 tiles of an
actual kerb. `tests/venue/test_floor.gd` proves both sides of the boundary: a
pedestrian at the far kerb waits for a car, while an indoor Promotions visitor
does not. `tools/visitor_flow_probe.gd` is the deterministic, save-isolated
arrival/departure probe used for the diagnosis.

Across three 120-second, level-8 runs, peak Promotions-door occupancy fell from
12–16 visitors to 6–8; moving clusters inside 0.35 tiles fell from 7–11 to 3–4;
and the final Promotions clump disappeared in all three seeds. Floor, city and
all-venue navigation suites pass on Godot 4.4.1 and 4.7.1.

The latest complete 4.4.1 suite remains **42 pass / 1 fail / 0 timeout of 43, in 237s**.
The only failure is still the same four owner-placement assertions in
`test_geometry.gd` listed below. The previously unverified seven-day

## Every open bug, by severity

### 1. Visitors move as one mass — FIXED in continuation

The most visible defect in the game, reported repeatedly. Measured on venue 1 at
staff level 8, 90s warm:

```
CLUMPS 5 at 11.7,12.5 { "rest": 3, "browse": 2 }
       3 at  1.8,13.0 { "exit": 1, "queue": 2 }
       3 at  6.0,11.9 { "browse": 1, "queue": 2 }
```

**Ruled out:** not missing speed variance — `randf_range(1.8, 2.5)` on spawn
(`venue_floor.gd:1670`) and `1.8..2.3` on the second path (`:2037`). Not the
seating system in isolation.

**Hypothesis, unverified** — two effects compounding:
1. *Chokepoint serialisation.* Everyone paths through the one-tile promotions
   doorway; throughput is set by the slowest visitor at the front, so jitter
   cannot disperse the line.
2. *`REST_CHANCE = 0.55`* (`:593`) with `REST_SECONDS 14..30` (`:595`) and seats
   sitting at that chokepoint.

**Agreed first move: instrument arrival-versus-departure timing at the doorway
before changing anything.** Even arrivals + bursty departures = seat hold.
Bursty arrivals = upstream. Local separation steering is likely needed either
way, but confirm the cause first. **Do not tune `REST_CHANCE` blind.**

## Tools

The placer is **not in the game**. `F9` exists only when `tools/place.gd` is the
running script — `tools/` is excluded from the Android export on purpose.
Launching the game normally gives no dev mode at all.

```bash
# interactive placer, starting on venue 1
godot --path ~/godot-saga/repo -s tools/place.gd -- \
    venue=whispering_pines cash=1e40 levels=8

# headless: every venue re-indexes correctly
GRAND_EXHIBIT_PLACER_SELFTEST=1 godot --headless --path . -s tools/place.gd -- \
    venue=whispering_pines sweep=1

# headless: a dragged clerk actually moves (not just the handle)
GRAND_EXHIBIT_PLACER_SELFTEST=1 godot --headless --path . -s tools/place.gd -- \
    venue=whispering_pines levels=8 stafftest=1

# full suite
bash tools/run_tests.sh
```

Controls: `F9` edit · `V` venue menu (1–12, `[` / `]` to step, Esc to close) ·
drag · shift = free placement · arrows nudge · `R` rotate 45° (shift 15°) ·
`M` mirror · `G` grid · `Ctrl+S` save · `Ctrl+Z` undo.

`Ctrl+S` rewrites the whole of `data/venues.json` and backs the previous copy up
first. That backup exists because a stray save once replaced every venue's
formatting.

**Only 4 posts per venue are draggable** — 2 gallery docents, 2 promotions
clerks. Ticket cashiers come from the counter window geometry (`_window_gx`,
`_counter_gy`) and porters from the vault drop point; neither reads `stations`,
so moving those still needs a code change. Worth unifying.

### The trap that cost a session

`_apply_live` for a station must **not** call `retheme()`. That rebuilds the theme
from `DataLoader`'s cached copy and silently discards the edit — the handle moves,
the person does not. It is also not enough to re-key `_cast_key`:
`_refresh_cast()` only ever *creates* and *destroys* staff nodes, never re-places
an existing one, because in the shipping game a post never moves. The working
sequence is: write into the live room dict, free that department's cast, then
refresh. `stafftest=1` asserts the person moved, not the handle.

## Hazards — carry these forward

* `godot-saga/` may be **open in a live editor**. The hazard is concurrent
  modification: **re-read before editing**. **No git operations in this tree.**
* The worktree is intentionally dirty (146 modified/untracked paths). Never
  `git reset --hard`, `git clean`, checkout, or discard untracked files.
* Never let tooling touch the live save at
  `~/.local/share/godot/app_userdata/Grand Exhibit/grand_exhibit_save.json`.
  The placer disables `SaveSystem` for exactly this reason.
* Do not copy IBT code, assets, copy, names, layouts or branded UI. Reference for
  gameplay familiarity only.
* Stable dept ids (`promotions`, `ticket`, `archive`, `gallery`) are save and API
  contracts.
* `python3 tools/author_venue.py` regenerates venues **4–12 only**. Venues 1–3
  are hand-authored.
