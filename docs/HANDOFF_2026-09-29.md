## Engineering rules that bite

- **GDScript warnings are errors.** A `:=` that infers from a Variant fails
  to compile. Type it explicitly (`var x: String = str(d.get(...))`).
  Dictionary `.get()` and `callv` results are Variants.
- **Test scripts** (`extends SceneTree`) must `load()` scripts that name
  autoloads at runtime, never `preload()` them, or the checks silently no-op.
  Tests refuse to run without `GRAND_EXHIBIT_TEST_RUN=1`. Booting
  `main.tscn` starts a new game, so set reputation and other state after
  boot.
- **The runner fails a test on** any `FAIL` line, `SCRIPT ERROR`, or engine
  `ERROR:`, including "resources still in use at exit". If a test clicks
  buttons, `await create_timer(0.8).timeout` before `quit()` so the click
  sound finishes (see `test_managers.gd`).
- **Coroutines in long-lived nodes:** never await a SceneTreeTimer, a tween
  or a foreign signal. Use child `Timer`s (`_wait()`), check `_alive(n)` after
  every await, and in `_exit_tree` emit `arrived` on NPCs and `timeout` on
  pending timers so suspended calls are released. See `venue_3d.gd` and
  `cafe_world.gd`.
- **Rendering:** Compatibility renderer. Linear tonemap only (Filmic bleaches
  toy colours). Light, backdrop and colour grading for every 3D world come
  from `scripts/render/toy_look.gd` (sun 0.6, warm-neutral ambient 0.4,
  saturation 0.78, soft shadows). Its `watch()` flattens every material that
  enters the world to matte (roughness ≥ 0.88, low specular, Lambert wrap);
  gold uses `ToyLook.gilt()`. Don't set lights or environments per scene.
- **Open plan:** `venue.py` builds no "inner" walls (both sides inside rooms
  on the same level). `data/venues.json` still lists them: rooms, doors and
  the retired 2D floor read that data, so leave it. A wall-hung exhibit on a
  removed wall gets a freestanding feature wall and a vault door a portal
  (`feature_walls`); columns skip exhibit/prop footprints (`blocked`). Signs
  are sized for the longest translation of the room name.
- **UI look:** every colour, radius and button state comes from
  `scripts/ui/museum_chrome.gd` (tokens + `panel()`/`button()`) and
  `scripts/ui/ui_kit.gd`. Text on a filled button follows the fill
  (`Chrome.on_color`). No thick rims, no outlined lettering, no cream or brass
  surfaces; highlight with the action colour or a notification dot. The UI
  face is Inter (SemiBold/Medium, subset); Quicksand only letters 3D signs.
- **Grid ↔ world:** grid `(gx, gy)` is Godot `(gx, height, gy)` and Blender
  `(gx, -gy, z)`. With `size`, `at` is the top-left corner; without it, `at`
  is the centre (`venue_3d.gd _place`).
- **Editing `data/wings.json`:** don't `json.dump` the whole file; that
  reformats 3000 lines. Splice entries in, keeping the compact one-exhibit-
  per-line style.
- **Wings:**
  - Authored floors (with a `layout`) are terraces behind the building. Their
    podium is built from the ground up.
  - A museum that has theme storeys (rooms with `level >= 1`) lists them
    first as `floor_N` entries without a layout. Keep those ids; saves
    reference them.
  - Lifts rise from the floor below. `venue.py upper_floors` starts at the
    top theme storey.
  - `tests/meta/test_wings.gd` checks that every museum has a 2F and a 3F,
    and that each authored floor keeps its pieces on the floor.
- **Performance:** `Economy.venue_rates` sits on a perf budget
  (`test_performance`, 10k calls < 2 s, now about 1.5–1.75 s). Don't add
  per-call scans; pass `manager_multipliers()` through as it does now.
