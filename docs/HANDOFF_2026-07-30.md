## What changed this session

### 1. Idle porters no longer hide the vault staff

`PORTER_IDLE_ALPHA` was 0.42. At low transport levels there is exactly **one**
porter and it is idle nearly all the time, so the vault read as unstaffed —
reported by the owner as "I don't see the vault managers". Now the **last**
porter never fades; only the second and third do, at 0.55.

The general lesson: fading something to mean "spare capacity" only parses when
there is a crew to be spare from.

### 2. Staff posts are draggable in the placer

Staff stand on each room's `stations`, authored as offsets **inside** the room
rather than as absolute grid points, so a tool that only understood props could
not see them at all. `tools/place.gd` now indexes them, converts to absolute for
the drag and writes the offset back.

**Only 4 posts per venue are draggable** — 2 gallery docents, 2 promotions
clerks. Ticket cashiers are placed from the counter window geometry
(`_window_gx`, `_counter_gy`) and porters from the vault drop point; neither
reads `stations`, so moving those still needs a code change. Worth unifying.

### 3. Venue picker in the placer

`V` opens a menu of all twelve; click a row, or `[` / `]` to step, Esc to close.
Switching goes through `retheme()` — the same call the game uses — so cast,
surround, storey nodes and queues all rebuild. Cash and purchased levels carry
across untouched. Verified headlessly across all twelve; every one re-indexes
onto the correct theme (`sweep=1`, below).

Venues **4–12 are marked `*` in amber**: they are emitted by
`tools/author_venue.py`, so hand placements survive in `venues.json` but are
destroyed by the next generator run. Venues 1–3 are hand-authored JSON and safe.
When placements in a starred venue are worth keeping, fold them back into the
generator.

### 4. Gallery is the only department that can show zero staff

Not changed — it needs an owner decision.

## Open bugs

### A. Visitors move as one mass — TOP PRIORITY, unsolved

The owner has reported this repeatedly and it is the most visible defect in the
game. Measured on venue 1 at staff level 8, 90s warm:

```
CLUMPS 5 at 11.7,12.5 { "rest": 3, "browse": 2 }
       3 at  1.8,13.0 { "exit": 1, "queue": 2 }
       3 at  6.0,11.9 { "browse": 1, "queue": 2 }
```

What has been **ruled out**:

* Not missing speed variance — `v.speed = randf_range(1.8, 2.5)` on spawn
  (`venue_floor.gd:1670`) and `1.8..2.3` on the second path (`:2037`).
* Not the seating system in isolation. An earlier measurement put the biggest
  clump at the promotions doorway (gx 10.5, gy 10.35–12.1) around benches the
  owner had placed, and the same area is the largest clump today.

Working hypothesis, **not yet verified** — two effects compounding:

1. **Chokepoint serialisation.** Everyone paths through the same one-tile
   promotions doorway. Speed jitter cannot disperse a queue whose throughput is
   set by the slowest visitor at the front, so they arrive as a line and leave as
   a line.
2. **`REST_CHANCE = 0.55`.** Over half of arriving visitors try to sit, seats sit
   right at that chokepoint, and a held seat lasts `REST_SECONDS 14..30`. Bodies
   accumulate where traffic is already narrowest.

Suggested next step: instrument arrival times at the doorway before changing
anything — if they arrive evenly and *leave* in a burst, it is the seat hold; if
they arrive in a burst, it is upstream. Local separation steering is likely
needed regardless, but confirm the cause first. Do not tune `REST_CHANCE` blind.

### B. Venue 1 room density

Gallery is at 11 props against a floor of 12; archive at 6 against 7. Adding two
pieces to each clears the suite. Coordinate with the owner — they are actively
placing in venue 1 and their layout intent wins over the minimum.

## Tools

The placer is **not in the game**. `F9` exists only when `tools/place.gd` is the
running script — `tools/` is excluded from the Android export on purpose. The
owner hit this: launching the game normally gives no dev mode at all.

```bash
# interactive placer, starting on venue 1
godot --path ~/godot-saga/repo -s tools/place.gd -- \
    venue=whispering_pines cash=1e40 levels=8

# headless: every venue re-indexes correctly
GRAND_EXHIBIT_PLACER_SELFTEST=1 godot --headless --path . -s tools/place.gd -- \
    venue=whispering_pines sweep=1

# headless: a dragged clerk actually moves (not just the handle)
GRAND_EXHIBIT_PLACER_SELFTEST=1 godot --headless --path . -s tools/place.gd -- \
    venue=whispering_pines levels=8 stafftest=1
```

Controls: `F9` edit · `V` venue menu · drag · shift = free placement · arrows
nudge · `R` rotate 45° (shift 15°) · `M` mirror · `G` grid · `Ctrl+S` save ·
`Ctrl+Z` undo.

`Ctrl+S` rewrites the whole of `data/venues.json` and backs the previous copy up
first. That backup exists because a stray save once replaced every venue's
formatting.

### A trap worth knowing

`_apply_live` for a station must **not** call `retheme()`. That rebuilds the
theme from `DataLoader`'s cached copy and silently discards the edit — the
handle moves, the person does not. It also is not enough to re-key `_cast_key`:
`_refresh_cast()` only ever *creates* and *destroys* staff nodes, never re-places
an existing one, because in the shipping game a post never moves. The working
sequence is: write into the live room dict, free that department's cast, then
refresh. `stafftest=1` asserts the person moved, not the handle.

## Hazards — carry these forward

* `godot-saga/` is open in a live editor. The hazard is **concurrent
  modification**, so re-read before editing. No git operations in this tree.
* The worktree is intentionally dirty. Never `git reset --hard`, `git clean`,
  checkout, or discard untracked files.
* Never let tooling touch the live save at
  `~/.local/share/godot/app_userdata/Grand Exhibit/grand_exhibit_save.json`.
  The placer disables `SaveSystem` for exactly this reason.
* `data/store_iap.json → ads` still holds Google's **TEST** ad units with
  `is_test: true`. Release blocker — see `ANDROID_RELEASE.md` §7.
* Do not copy IBT code, assets, copy, names, layouts or branded UI. Reference for
  gameplay familiarity only.
* Stable dept ids (`promotions`, `ticket`, `archive`, `gallery`) are save and API
  contracts.
* `python3 tools/author_venue.py` regenerates venues **4–12 only**. Venues 1–3
  are hand-authored.

## Working agreements learned the hard way

* Do not fix what is not broken. Two benches were moved unasked and had to be
  reverted.
* A mirror is not a rotation. No angle reflects an asymmetric shape.
* Verify the claim the owner actually cares about. "The file changed", "the floor
  redrew" and "the person moved" are three different claims, and only the last
  one was what "drag a clerk" meant.
* Layouts are open-plan and explorable, never one section stacked in front of the
  last.
* Venues 4–6 are the visual reference. 1–3 read as too plain.
